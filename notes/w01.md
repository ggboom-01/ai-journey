## 我学到的东西

### 概念

- **Agent ≠ 聊天机器人。** 区别只有一个：Agent 的模型可以**自己决定去调用工具**，从而碰到真实世界的数据。聊天机器人只能靠脑子里记的东西，算错了也照样自信。
- **工具调用的流程是 4 步循环**：提问（带工具清单）→ 模型返回 tool_calls → **我的代码**真正执行工具 → 把结果塞回对话，回到第一步。
- **执行工具的是我的 Python 代码，不是模型。** 模型只输出一段"我想调用 calculator，参数是 xxx"的 JSON。所以 Agent 的能力上限 = 我给它写的工具的上限。
- **一次可以调用多个工具。** 实测里模型在一个回合里同时要了 `get_time` 和 `calculator`。
- **链式调用才是关键。** 第 2 步的参数可以由第 1 步的结果决定（先 `list_files` 看到 `notes.txt`，再 `read_file` 读它）。
- **工具的 `description` 是写给模型看的说明书**，写得含糊它就不知道什么时候该用。
- **防死循环三板斧**：最大步数、总耗时上限、重复调用检测。三条都是代码里几行的事，但生产环境必配。

核心循环（`agent.py` 里的 `run_agent`，简化版）：

```python
while step < MAX_STEPS:
    msg = chat(messages)                      # ① 带上工具清单问模型
    if not msg.get("tool_calls"):             # ② 它不要工具了 = 可以回答，结束
        return strip_think(msg["content"])
    messages.append(msg)                      # ③ 记下它的工具调用意图
    for call in msg["tool_calls"]:
        result = TOOLS[call.name][0](**call.args)   # ④ 我的代码真正执行
        messages.append({"role": "tool", "content": result})  # ⑤ 结果塞回去
```

## 踩的坑

| 问题 | 原因 | 怎么解决的 |
|---|---|---|
| `ollama` 命令在 PowerShell 里找不到 | 装完没重开终端，PATH 没刷新 | 重开一个终端；其实服务已经在后台跑着，`curl 127.0.0.1:11434` 直接能通 |
| 终端里中文全是乱码 | Windows PowerShell 控制台默认 GBK，Python 却按 UTF-8 输出 | 代码里读 `GetConsoleOutputCP()` 自适应编码；另外备了 `run.bat` 先 `chcp 65001` |
| 提交信息里的中文变成乱码 | Windows 下把中文当参数传给 git 会被转成 ANSI | 把提交信息写成 UTF-8 文件，用 `git commit -F 文件` |
| 第一次 commit 的作者邮箱被写成了 `{"message":"Not Found"...}` | 调 GitHub 接口查邮箱时权限不足返回 404，且报错走了标准输出，被当成邮箱记了进去 | 校验邮箱格式 + 用 `用户名@users.noreply.github.com` 兜底，再 `commit --amend --reset-author` |
